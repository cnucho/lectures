# 정책연구자를 위한 텍스트·영상 분석 이해와 실행 가이드

## 1. 이 가이드의 목표

이 가이드의 목표는 전산 분석가를 양성하는 것이 아니다. 정책연구자가 다음을 스스로 판단하고 책임질 수 있게 하는 것이 목표다.

- 정책질문에 맞는 자료와 분석방법을 선택한다.
- 분석 결과가 무엇을 말할 수 있고 무엇을 말할 수 없는지 구분한다.
- 표본, 측정, 코딩, 인과추론의 약점을 발견한다.
- 자동화 도구와 전산전문가에게 일을 맡기더라도 핵심 결정을 넘기지 않는다.
- 정책결정자에게 불확실성과 한계를 포함해 결과를 설명한다.

정책연구자가 모든 알고리즘을 구현할 필요는 없다. 그러나 분석 대상, 자료의 범위, 분석 단위, 측정 규칙, 비교 기준, 타당도, 인과주장의 수준은 직접 결정하고 설명할 수 있어야 한다.

## 2. 설명의 깊이를 네 단계로 구분한다

앱과 교육자료에서 모든 분석방법을 같은 깊이로 설명하면 안 된다. 각 항목에는 다음 학습표지를 붙인다.

| 학습표지 | 정책연구자에게 요구되는 수준 | 평가 질문 |
|---|---|---|
| `개념` | 어떤 문제에 쓰는지와 핵심 한계를 안다. 수식이나 구현은 몰라도 된다. | 이 방법을 왜 쓰며, 무엇을 증명하지 못하는가? |
| `필수이해` | 결과를 읽고 오류·과장·오용을 판별할 정도로 이해한다. | 이 결과를 믿기 전에 무엇을 확인해야 하는가? |
| `직접설계` | 연구 프로토콜과 판단 기준을 정하고 결과를 승인할 수 있다. | 자료·단위·코드·비교·품질 기준을 직접 정할 수 있는가? |
| `전문가협업` | 구현은 전산전문가에게 맡기되 요구사항과 검증 기준을 제시한다. | 전문가에게 무엇을 요구하고 어떤 시험 결과를 받아야 하는가? |

한 분석방법 안에서도 요구 수준이 다르다. 예를 들어 토픽 모델의 수학적 최적화는 `개념` 또는 `전문가협업` 수준이면 충분하지만, 토픽을 정책현실의 객관적 범주로 오해하지 않는 것은 `필수이해`, 토픽 수·해석·안정성 검토 규칙을 정하는 것은 `직접설계`에 해당한다.

## 3. 정책연구자가 반드시 잘 이해해야 하는 공통 토대

다음은 특정 기법보다 중요하다. 모든 정책 텍스트·영상 분석에서 `필수이해` 또는 `직접설계` 수준으로 다뤄야 한다.

### 3.1 정책질문과 분석 목적 — `직접설계`

먼저 무엇을 알고 싶은지 구분한다.

- 기술: 어떤 주제·표현·입장·프레임이 얼마나 나타나는가?
- 비교: 집단, 기관, 매체, 지역, 시기 사이에 무엇이 다른가?
- 해석: 문제와 책임, 정당성, 대상집단이 어떤 언어로 구성되는가?
- 설명: 왜 이런 반응이나 변화가 나타났는가?
- 효과: 정책 또는 캠페인이 결과를 변화시켰는가?

기술과 해석의 결과만으로 정책효과를 주장할 수 없다. 효과 질문에는 비교대상, 정책 이전 기준선, 시간 변화, 대안 설명을 다룰 연구설계가 추가로 필요하다.

### 3.2 모집단, 자료범위, 표본 — `직접설계`

수집된 문서 전체가 관심 모집단을 대표하는 것은 아니다. 연구자는 최소한 다음을 기록해야 한다.

- 포함하려는 모집단과 실제 접근 가능한 자료의 차이
- 검색어, 채널, 기간, 언어, 지역, 문서유형
- 포함·제외 규칙과 중복 제거 규칙
- API 제한, 삭제된 게시물, 비공개 자료, 유료벽 등 누락 원인
- 전수수집인지 표본인지, 표본이면 추출방식과 편향 가능성
- 수집 시각과 조회수·좋아요 같은 변동 지표의 스냅숏 시각

“많이 모았다”는 “대표성이 있다”와 같지 않다. 검색 결과 상위 문서, 많이 공유된 글, 추천 알고리즘에 노출된 영상만 모으면 가시성은 분석할 수 있어도 전체 여론을 대표한다고 말하기 어렵다.

### 3.3 분석 단위와 분모 — `직접설계`

문서, 기사, 게시물, 댓글, 발화 차례, 문장, 의미단위, 영상, 자막 구간은 서로 다른 분석 단위다. 다음을 사전에 정한다.

- 한 행 또는 한 코딩 단위가 무엇인가?
- 하나의 단위에 여러 코드를 허용하는가?
- 비교 비율의 분모는 문서 수인가, 발화 수인가, 작성자 수인가?
- 같은 사람이 쓴 여러 댓글을 독립 관측치로 취급하는가?
- 긴 문서와 짧은 게시물을 같은 무게로 비교하는가?

단위와 분모가 달라지면 같은 자료에서도 결론이 달라질 수 있다.

### 3.4 구성개념과 측정 — `직접설계`

“정책수용성”, “불신”, “낙인”, “책임귀인”, “프레임”은 원자료에 그대로 들어 있는 값이 아니다. 연구자가 이론과 규칙으로 측정한다.

- 구성개념의 정의
- 관찰 가능한 지표
- 포함·제외 기준
- 경계사례와 반례
- 하나의 표현이 여러 의미를 가질 때 처리 규칙
- 다른 자료나 지표와 비교하는 타당화 계획

모델의 정확도가 높아도 잘못 정의한 개념을 정확하게 반복 측정할 수 있다. 기술적 정확도와 개념 타당도는 다르다.

### 3.5 신뢰도, 타당도, 재현가능성 — `필수이해` + `직접설계`

- 신뢰도: 같은 규칙을 적용할 때 결과가 일관되는가?
- 타당도: 연구하려는 개념을 실제로 잘 측정하는가?
- 재현가능성: 다른 사람이 자료와 절차를 따라 결과를 확인할 수 있는가?

사람 간 코딩 일치도는 중요하지만 그것만으로 타당도가 증명되지는 않는다. 두 사람이 같은 잘못된 규칙에 동의할 수도 있다. 최소 품질체계는 다음을 함께 포함한다.

1. 명확한 코드북과 경계사례
2. 소규모 독립 이중코딩
3. 불일치 원인 검토와 코드북 개정
4. 모델 또는 자동코딩의 층화 표본검증
5. 틀린 양성·틀린 음성·소수범주 별도 점검
6. 원문 근거와 결정 이력 보존
7. 새 시기·새 출처에 대한 성능 저하 점검

전수 인간코딩이 어렵다면 대표·희귀·불확실·고위험 사례를 섞은 검증표본을 사용한다. 검증표본을 모델 개선용 자료와 최종 평가용 자료로 분리해야 자기검증을 피할 수 있다.

### 3.6 인과주장의 수준 — `필수이해`

다음 표현을 구분한다.

- 관찰: 자료에서 어떤 패턴이 보였다.
- 연관: 두 현상이 함께 변했다.
- 기여: 정책이 변화에 기여했다는 여러 근거가 있다.
- 인과효과: 적절한 반사실 비교에서 정책 때문에 결과가 달라졌다고 판단한다.

텍스트·영상 자료는 정책의 도달, 프레임, 반응, 집행과정, 작동기제를 잘 보여줄 수 있다. 그러나 그 자료만으로 최종 정책효과를 입증하는 경우는 드물다.

## 4. 분석방법별로 어디까지 알아야 하는가

| 분석방법 | 주된 정책용도 | 정책연구자가 잘 알아야 할 것 | 구현은 맡겨도 되는 것 | 금지해야 할 과장 |
|---|---|---|---|---|
| 빈도·키워드·N-gram | 의제, 용어, 반복표현 탐색 | 전처리, 분모, 문서길이, 동의어·부정어의 영향 (`필수이해`) | 토큰화기 구현과 대용량 최적화 (`전문가협업`) | 빈도가 곧 중요성·찬성·효과라는 주장 |
| 사전 기반 분석 | 미리 정한 개념의 빠른 탐색 | 사전의 영역 적합성, 문맥 오분류, 부정·반어 (`필수이해`) | 형태소 분석과 사전 매칭 엔진 (`전문가협업`) | 단어 출현을 복합 개념의 완전한 측정으로 간주 |
| 내용분석·주관식 코딩 | 명시적 범주 측정과 집단 비교 | 코드북, 단위, 복수코딩, 표본, 신뢰도 (`직접설계`) | 코딩 UI와 자동 분류 파이프라인 (`전문가협업`) | 자동코딩 결과를 검증 없이 확정값으로 사용 |
| 감성·정서·입장 분석 | 긍정·부정, 정책 찬반, 대상별 태도 탐색 | 감성과 입장은 다르며 대상이 명시돼야 함 (`필수이해`) | 분류모델 학습·배포 (`전문가협업`) | 부정적 문장이 정책 반대 또는 불만족이라는 단정 |
| 지도학습 분류 | 대규모 자료의 일관된 범주화 | 학습표본, 클래스 불균형, 오류비용, 외부검증 (`직접설계`) | 모델 구조·튜닝·서빙 (`전문가협업`) | 전체 정확도 하나로 신뢰성을 주장 |
| 토픽 모델링 | 대규모 코퍼스의 탐색적 주제 후보 발견 | 토픽은 발견된 사실이 아니라 모델 산출물이며 사람이 해석·검증함 (`필수이해`) | 임베딩, 차원축소, 군집화, 하이퍼파라미터 (`전문가협업`) | 토픽 수·명칭을 객관적 사회범주로 간주 |
| 임베딩·유사도·군집 | 유사 문서 검색, 중복·패턴 탐색 | 유사도 기준과 모델 선택에 따라 이웃이 바뀜 (`개념`/`필수이해`) | 벡터 인덱스와 모델 최적화 (`전문가협업`) | 가까운 문서가 같은 의미·원인·입장이라고 단정 |
| 개체명·관계 추출 | 기관·정책·지역·인물의 언급 지도 | 동명이인, 약칭, 관계의 방향과 근거 (`필수이해`) | 추출 모델과 지식그래프 구현 (`전문가협업`) | 함께 언급된 것을 실제 관계나 영향으로 해석 |
| 주제분석·프레임워크 분석 | 경험·장벽·집행과정의 패턴 해석 | 사례 맥락, 부정사례, 연구자 해석, 포화 주장 (`직접설계`) | 검색·정렬·인용 연결 보조 (`전문가협업`) | 출현 수만으로 주제의 의미를 확정 |
| 프레임 분석 | 문제정의, 원인·책임, 도덕평가, 처방 비교 | 이론모형, 프레임 요소, 행위자·청중·맥락 (`직접설계`) | 후보 구간 탐색과 반복 코딩 보조 (`전문가협업`) | 빈도만으로 프레임의 지배력·효과를 주장 |
| 담론·비판적 분석 | 범주, 정당성, 배제, 권력관계 해석 | 분석 전통, 제도·역사 맥락, 반대해석, 연구자 위치성 (`직접설계`) | 코퍼스 탐색과 인용 관리 (`전문가협업`) | 단어 목록이나 LLM 요약을 담론분석으로 부르기 |
| 서사·수사 분석 | 정책문제의 이야기 구조와 설득전략 분석 | 순서, 행위자성, 전환점, 전체 맥락 (`직접설계`) | 사건·표현 후보 추출 (`전문가협업`) | 문장을 분리해 전체 서사의 의미를 뒤집기 |
| 문헌근거 종합 | 정책질문별 근거 비교와 공백 확인 | 검색범위, 선정기준, 질평가, 적용가능성 (`직접설계`) | 검색 보조·중복 제거·표 추출 (`전문가협업`) | 검색된 문헌이 망라적이라고 자동 가정 |
| 효과평가·다원자료 종합 | 정책·캠페인의 과정, 기제, 성과 판단 | 변화이론, 비교집단, 기준선, 시차, 교란, 결과 위계 (`직접설계`) | 통계 추정·대규모 연결·민감도 분석 (`전문가협업`) | 참여·조회·긍정댓글을 최종 효과로 간주 |

## 5. 정책효과 분석에서 텍스트와 영상 자료의 위치

### 5.1 먼저 변화이론을 만든다 — `직접설계`

정책이나 캠페인이 어떤 경로로 결과를 만들 것인지 연결한다.

```text
투입 → 집행활동 → 산출 → 도달·노출 → 인지·해석·반응
     → 태도·의도 → 행동 → 중간성과 → 최종 정책성과
```

텍스트·영상 분석은 주로 집행, 산출, 도달, 메시지, 프레임, 반응, 장벽, 작동기제를 측정한다. 행정자료, 조사자료, 실험·준실험 자료는 행동과 성과의 변화 및 인과효과 판단에 더 직접적으로 쓰인다.

### 5.2 효과 증거를 층위별로 분리한다

| 증거 층위 | 예시 | 가능한 판단 | 아직 할 수 없는 판단 |
|---|---|---|---|
| 집행·산출 | 보도자료, 지침, 광고물, 집행기록 | 계획한 활동과 메시지가 생산되었는가 | 대상자에게 실제로 도달했는가 |
| 도달·노출 | 조회, 배포, 보도량, 노출추정 | 어느 채널과 시기에 도달이 컸는가 | 노출이 태도나 행동을 바꿨는가 |
| 수용·반응 | 댓글, 주관식 응답, 인터뷰, 민원 | 어떻게 이해·수용·거부했는가 | 반응자가 전체 대상집단을 대표하는가 |
| 기제·맥락 | 담론, 인터뷰, 집행자 기록 | 왜 작동했거나 막혔는가 | 기제만으로 효과 크기가 얼마인가 |
| 행동·성과 | 신청, 이용, 위반, 건강·경제 지표 | 결과가 얼마나 변했는가 | 정책 때문에 변했는가 |
| 인과효과 | 실험, 비교집단, 중단시계열, 차이의 차이 등 | 대안 설명을 줄인 정책효과 | 모든 맥락에 동일하게 적용되는가 |

정책연구자는 위 표의 구분과 인과논리를 `필수이해`해야 한다. 회귀모형의 세부 구현은 전문가에게 맡길 수 있지만, 비교대상과 결과변수, 정책시점, 시차, 교란요인, 민감도 분석 요구는 직접 정해야 한다.

### 5.3 여러 자료를 종합할 때의 원칙

- 자료마다 맡는 증거 역할을 먼저 정한다: 효과크기, 집행, 도달, 반응, 기제, 맥락 중 무엇인가.
- 서로 다른 모집단과 분석 단위를 하나의 비율로 합치지 않는다.
- 같은 방향의 결과만 모으지 말고 불일치와 무효과도 보존한다.
- 텍스트 해석을 수치 효과크기로 꾸미지 않는다.
- 통계적 효과가 있어도 정책적 중요성, 형평성, 실행가능성을 별도로 판단한다.
- 종합 결과에는 확실성, 적용 범위, 누락 자료, 대안 설명을 함께 제시한다.

## 6. 자료원별 수집과 해석 원칙

### 6.1 정책문서·법령·의회자료·기관자료

정책의 공식 목적, 설계, 책임, 집행규칙을 분석하기 좋다. 실제 집행과 대상자의 경험을 그대로 보여주지는 않는다. 문서의 버전, 시행일, 관할, 작성기관, 문서 간 위계를 보존한다.

### 6.2 언론보도

의제설정, 출처 활용, 프레임, 책임귀인, 보도량 변화를 분석할 수 있다. 매체 선정, 기사 DB의 수록범위, 중복 전재, 통신사 기사, 검색어 변화, 유료벽을 기록해야 한다. 보도량은 여론 또는 정책효과와 같지 않다.

### 6.3 소셜미디어

자발적 반응, 논쟁, 확산경로, 커뮤니티별 담론을 볼 수 있다. 그러나 이용자 구성, 추천 알고리즘, 봇·조직행동, 삭제, 비공개 콘텐츠, API 제공범위 때문에 일반 국민의 대표표본으로 보기 어렵다.

플랫폼별 자료를 합칠 때는 사용자, 게시물, 댓글, 공유, 해시태그를 같은 단위로 섞지 않는다. 공개 자료라도 개인정보, 재식별, 직접인용 검색가능성, 플랫폼 약관을 검토한다.

### 6.4 YouTube와 온라인 영상

자료 층위를 분리한다.

- 영상 메타데이터: 제목, 채널, 게시일, 길이, 조회수 스냅숏
- 자막·전사: 발화 내용과 시점
- 댓글: 일부 시청자의 공개 반응
- 시청각 장면: 화면, 인물, 상징, 편집, 음악, 자막 그래픽

자막만 분석하고 영상을 분석했다고 보고하면 안 된다. 자동자막은 발화자, 전문용어, 방언, 숫자를 틀릴 수 있으므로 검수표본을 둔다. 조회수와 댓글은 인과효과가 아니라 도달·참여의 일부 지표다. 시청각 코딩은 별도의 코드북, 시간구간 단위, 장면 근거가 필요하다.

### 6.5 조사 주관식·인터뷰·FGI

주관식 응답은 질문문구와 조사표본의 영향을 받는다. 인터뷰와 FGI는 발화 순서, 질문자 영향, 참여자 관계, 집단 상호작용을 보존해야 한다. 인용문을 고를 때 대표사례뿐 아니라 반례와 소수경험도 검토한다.

### 6.6 행정·성과·광고 자료

텍스트 반응과 실제 결과를 연결하려면 동일 기간, 대상집단, 지역, 캠페인 또는 정책 식별자를 확보한다. 클릭, 도달, 전환, 신청, 이용, 민원, 행동지표의 정의와 분모가 서로 다르므로 지표사전을 만든다. 개인정보 연결은 목적제한, 최소수집, 접근통제, 비식별화 기준을 따른다.

## 7. 표준 실행절차

### 1단계. 결정과 연구질문을 정의한다 — `직접설계`

- 누가 어떤 결정을 내리는 데 사용할 것인가?
- 기술, 비교, 해석, 설명, 효과 중 어느 질문인가?
- 잘못된 결론의 정책 위험은 무엇인가?

### 2단계. 프로토콜을 먼저 고정한다 — `직접설계`

- 모집단, 자료원, 기간, 검색식, 포함·제외 기준
- 분석 단위, 분모, 비교집단
- 구성개념, 코드북, 사람 검토 비율
- 개인정보·저작권·약관 처리
- 중단기준과 방법 변경 기록 방식

탐색 중 방법을 바꿀 수는 있다. 다만 바꾼 이유와 시점, 영향을 새 버전으로 남겨 사후적으로 유리한 방법만 고른 것처럼 보이지 않게 한다.

### 3단계. 수집범위와 누락을 기록한다 — `직접설계`

자료수집 도구는 검색과 저장을 돕지만 망라성을 자동 보장하지 않는다. 검색로그, API 응답, 실패, 중복, 제외 사유, 수집일을 원자료와 함께 보관한다.

### 4단계. 탐색분석을 한다 — `필수이해`

빈도, N-gram, 검색, 유사도, 토픽 후보로 자료의 구조와 오류를 찾는다. 이 단계의 산출물은 코드북과 가설을 만드는 단서이지 곧바로 최종 발견이 아니다.

### 5단계. 코딩·해석하고 근거를 연결한다 — `직접설계`

모든 코드와 해석은 문서 ID, 위치, 원문 구간으로 되돌아갈 수 있어야 한다. 자동화는 확실한 반복작업을 맡고, 애매함·희귀사례·고위험 판단은 사람에게 보낸다.

### 6단계. 품질을 검증한다 — `직접설계`

- 독립 검증표본과 불일치 검토
- 범주별 정밀도·재현율 또는 코더 일치도
- 출처·시기·집단별 오류 편차
- 부정사례와 대안 해석
- 결과의 전처리·모델·표본 민감도

단일 점수로 통과시키지 않는다. 연구목적에 중요한 오류가 무엇인지 먼저 정한다.

### 7단계. 다른 증거와 종합한다 — `필수이해`

텍스트·영상 결과를 행정자료, 조사, 통계, 문헌근거와 연결하되 각 자료의 역할과 한계를 유지한다. 수렴, 불일치, 미측정 영역을 모두 보고한다.

### 8단계. 주장 수준을 제한해 보고한다 — `직접설계`

보고서에는 질문, 자료범위, 단위, 방법, 검증, 주요 결과, 반례, 불확실성, 일반화 범위, 인과주장 수준, 감사 가능한 산출물 위치를 포함한다.

## 8. 앱은 무엇을 해야 하는가

### Text Analysis Copilot

정책연구자의 판단을 대신하는 자동 답변기가 아니라, 다음을 강제하고 보조하는 분석 작업공간이어야 한다.

- 연구질문과 분석 단위 확인
- 방법 팩과 프로젝트별 프로토콜 분리
- 자료·코드북·모델·결과 버전 관리
- 탐색, 코딩, 프레임·담론 해석 보조
- 원문 근거 연결과 불확실 사례 대기열
- 사람 검토, 신뢰도, 타당도 점검
- 주장 범위와 한계가 포함된 내보내기

### Evidence Ledger와 수집 도구

자료를 “찾아주는” 것에서 끝나지 않고 다음을 남겨야 한다.

- 어디서 무엇을 어떤 식과 기간으로 찾았는가
- 무엇을 포함·제외했고 왜 그랬는가
- 어떤 자료에 접근하지 못했는가
- 각 주장과 수치가 어느 원문·위치에서 왔는가
- 사람이 어떤 후보를 승인·기각했는가

Evidence Ledger는 검색의 완전성을 보증하는 도구가 아니라, 검색범위와 판단을 감사 가능하게 만드는 도구로 사용한다.

### 통계·인과분석 도구

텍스트 분석 결과를 정책효과로 연결할 때는 별도의 통계 설계와 분석도구가 필요할 수 있다. 앱은 효과를 자동 선언하지 말고 비교대상, 기준선, 시간, 분모, 불확실성, 자료연결 가능 여부를 확인한 뒤 적절한 분석으로 넘겨야 한다.

## 9. 앱에서 분석방법을 설명하는 표준 형식

모든 방법 설명 화면과 방법 팩은 다음 순서를 따른다.

1. **정책결정 질문**: 어떤 결정을 지원하는가?
2. **이 방법이 관찰하는 것**: 자료에서 실제로 측정하는 것은 무엇인가?
3. **말할 수 없는 것**: 대표성·의도·인과효과 등 어떤 주장을 금지하는가?
4. **필요 자료와 분석 단위**: 어떤 자료를 어떤 단위로 다루는가?
5. **정책연구자가 직접 정할 것**: 범위, 개념, 코드, 비교, 품질 기준은 무엇인가?
6. **도구가 자동화할 것**: 반복 처리, 후보 추출, 검색, 계산은 무엇인가?
7. **필수 품질점검**: 어떤 검증을 통과해야 하는가?
8. **결과 읽기 예시**: 허용되는 해석과 과장된 해석을 나란히 보여준다.
9. **전문가 협업 시점**: 어느 규모·위험·방법에서 전산·통계·법률·윤리 전문가가 필요한가?
10. **저장 산출물**: 프로토콜, 원자료 목록, 코드북, 모델·프롬프트 버전, 검증표, 결정 로그, 보고서.

분석방법의 첫 화면에서 알고리즘 이름과 설정값을 먼저 제시하지 않는다. 정책질문, 자료, 단위, 가능한 주장, 위험을 먼저 보여주고 기술 설정은 필요할 때 펼쳐보게 한다.

## 10. 정책전문가 교육과정

| 모듈 | 도달 목표 | 중심 수준 | 실습 산출물 |
|---|---|---|---|
| 1. 질문과 주장 | 기술·비교·해석·효과 질문을 구분한다 | `필수이해` | 같은 주제의 네 가지 연구질문 |
| 2. 자료와 표본 | 수집범위와 대표성 한계를 진단한다 | `직접설계` | 자료원 지도와 수집 프로토콜 |
| 3. 단위와 측정 | 구성개념을 코딩 가능한 규칙으로 만든다 | `직접설계` | 분석 단위 정의와 코드북 |
| 4. 탐색 도구 | 빈도·N-gram·토픽·유사도를 과장 없이 쓴다 | `필수이해` | 탐색 메모와 후보 범주 |
| 5. 코딩과 분류 | 사람·규칙·모델 코딩을 검증한다 | `직접설계` | 파일럿 코딩과 오류표 |
| 6. 질적 해석 | 주제·프레임·담론 방법의 차이를 적용한다 | `직접설계` | 근거 연결 해석 메모 |
| 7. 효과와 종합 | 텍스트·영상 증거를 변화이론과 효과설계에 배치한다 | `직접설계` | 효과 증거 매트릭스 |
| 8. 검증과 보고 | 반례·불확실성·인과수준을 포함해 보고한다 | `직접설계` | 감사 가능한 정책분석 보고서 |

수료 기준은 소프트웨어 조작 능력이 아니다. 학습자는 실제 사례에서 다음을 수행해야 한다.

- 부적절한 자료·방법·인과주장을 찾아 수정한다.
- 방법 선택 이유와 포기한 대안을 설명한다.
- 코드북과 검증표본을 설계한다.
- 자동 분석의 오류를 범주별로 해석한다.
- 정책결정자에게 결과와 한계를 함께 전달한다.

- [ ] 정책효과라면 비교대상, 기준선, 기간, 시차, 교란을 다뤘다.
- [ ] 개인정보, 저작권, 플랫폼 약관, 인용 위험을 검토했다.
- [ ] 프로토콜, 자료목록, 코드북, 버전, 결정로그를 보관했다.

## 12. 핵심 원칙

정책연구자에게 가장 중요한 역량은 도구를 많이 아는 것이 아니다. **좋은 질문을 만들고, 적절한 자료와 비교를 설계하고, 측정과 자동화의 오류를 발견하고, 증거보다 강한 주장을 하지 않는 능력**이다. 전산 도구는 이 판단을 빠르고 일관되며 감사 가능하게 만드는 보조수단이어야 한다.
